## 🟠 المستوى ٢ — فجوات متوسطة

- [ ] 🟠 **منتقي العنوان المحفوظ على الرئيسية + تمرير `addressId`** — Expo يعرض شريط عناوين ويمرّر العنوان المختار للطلب. Flutter `home_screen.dart` يستدعي `createRefill(customerId)` بلا `addressId` رغم دعم الـ repo له → الزبون متعدّد العناوين لا يختار وجهة التوصيل.
- [ ] 🟠 **حارس الطلب النشط (منع التكرار) على الرئيسية** — Flutter يعرض `_orderCard` بزرّ «اطلب الآن» مفعّلاً حتى مع وجود طلب جارٍ؛ المنع من الخادم فقط. Expo يحوّل الزرّ إلى «تتبّع طلبك الحالي».
- [ ] 🟠 **بوّابة `customerConfirmedAt` في تفاصيل الطلب** — Flutter يعرض «أكّد الاستلام»/«أبلغ» دائماً لأي طلب مكتمل (النموذج `RefillOrder` يفتقر للحقل أصلاً) → إمكان تأكيد مكرّر ولا حالة «تم التأكيد، شكراً».
- [ ] 🟠 **زرّ «افتح في خرائط Google» تحت خريطة طلب الزبون** — الخريطة المضمّنة موجودة، لكن لا زرّ ملاحة خارجية للوجهة (`Launchers.navigate` موجود ومستخدم لدى السائق فقط). *(خاضع أيضاً لباگ `<queries>` أعلاه.)*
- [ ] 🟠 **منتقي عنوان لكل جدولة** — Expo يربط الجدولة بعنوان محفوظ ويعرضه؛ Flutter `schedules_screen.dart` يجمع التواتر فقط رغم دعم `ScheduleInput.addressId`.
- [ ] 🟠 **تثبيت GPS لعنوان محفوظ (map-picker)** — Expo يلتقط lat/lng للعنوان؛ Flutter `addresses_screen.dart` يجمع نصّاً فقط رغم دعم `AddressInput` للإحداثيات → دقّة توصيل أضعف للعناوين غير الافتراضية.
- [ ] 🟠 **رئيسية السائق: فرز «الأقرب أولاً» + رقاقات المسافة** — Expo يفرز المهام بالأقرب (haversine من GPS) ويعرض مسافة كل بطاقة؛ Flutter يعرض ترتيب الخادم الخام بلا مسافات (الإحداثيات متوفّرة في `DriverTask`).
- [ ] 🟠 **خريطة مهمة السائق: علامة السائق الحيّة + مسافة/ETA** — `_CustomerMap` (liteMode) يعرض علامة الزبون فقط؛ Expo يضيف علامة السائق الحيّة وتراكب مسافة+ETA. *(الملاحة وحاجز ٥٠م موجودان.)*
- [ ] 🟠 **شريط عدم الاتصال عام (كلا التطبيقين)** — Expo يركّب `OfflineBanner` فوق كل الشاشات (`_layout.tsx`). Flutter: `_syncBanner` داخل رئيسية السائق فقط، **والزبون بلا شريط إطلاقاً** (رغم وجود `isOnlineProvider`). الشاشات التي تُجري كتابات أوفلاين (walkin/task/cash) بلا مؤشّر.
- [ ] 🟠 **PostHog: أحداث ناقصة** — Flutter يلتقط ٤ فقط (`order_placed`/`order_claimed`/`order_completed`/`shift_ended`). مفقودة: `login_success`/`login_failed`/`signup_started`/`signup_completed`/`order_cancelled_by_driver`.
- [ ] 🟠 **demo mode للسائق ناقص** — `DemoInterceptor` بلا فرعَي `GET /customers` (بحث الزبائن → نتائج فارغة في walk-in) و`GET /drivers/me/perf` (شاشة الأداء تعرض أصفاراً بدل بيانات تجريبية).
- [ ] 🟠 **Haptics: تغطية الزبون ناقصة** — `Hap` موصول في رئيسية الزبون فقط (place-order). مفقود في: login/orders/تقييم/addresses/schedules/support/intro. *(ادّعاء v-سابق «claim موصول للزبون» غير دقيق — لا claim في تطبيق الزبون.)*
